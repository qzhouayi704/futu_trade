# 交易计划与离线模拟第一轮

此模块只提供离线纸面账户，不是富途模拟账户，也不是已接入盘中运行的自动交易器。
没有券商执行依赖，不读 `.env`，不向真实账户发单，未修改 `ExecutionModeGate` 或 `V2Runtime` 的实盘禁用边界。

## 已实现

- 沿用 `strategy.assessments.EntryPlan` 作为上游意向，可通过 `PlanBuilder.from_entry_plan` 转换为定点金额、明确到期时间的 `EntrySetup`。
- 转换方必须用交易日历明确计划的有效期及退出时刻；不擅自把交易日数换成自然日，也不默默忽略尚未建模的加仓/退出条件。
- 按单笔风险、组合剩余风险、单股仓位、现有挂单、现金保留和每手股数向下定仓。不足一手就跳过。
- 每个 setup 和策略版本对应唯一计划；同一来源决策不能重复分配。计划参数不可在原标识下修改。
- 独立 SQLite 文件原子保存账户、现金预留、计划、模拟成交及命令去重记录。启动时核对现金、订单和成交；拒绝已有非模拟数据库及账户/费用配置变更。
- 限价入场、延迟后执行、盘口容量限制、部分成交、撤销未成交部分、入场到期、结构止损、可选固定止盈、持有期限退出。
- 退出由当前信息触发，最早使用后续有效盘口成交，能表现跳空损失；不会按事后最高点或理想止损价制造成交。
- 同事件重放不重复执行，同时间盘口不重复消费，乱序接收时间回滚整个命令，过期/未来/无效盘口不能成交。
- 退出已触发但休市或没有盘口时保留任务，账本重新打开后仍可继续；持仓成交不因撤掉剩余买单而被抹掉。

## 运行

在仓库根目录使用现有 `uv` 环境：

```bash
bash scripts/run_paper_replay.sh \
  --input tests/fixtures/paper_replay_v1.json \
  --ledger backtest_results/paper-demo.db
```

账本父目录需存在。Windows 可用 Git Bash 执行脚本。重复输入相同文件会返回原命令结果，不新增成交。
换资金配置、费用参数或账户标识时必须使用新的账本文件，不覆盖旧实验。

输入采用 JSON `schema_version: 1`，包含 `account_id`（必须以 `paper:` 开头）、`policy` 和按接收时间排列的 `events`。支持四种命令：`plan`、`book`、`clock`、`cancel_entry`，完整字段见 fixture。

`policy.initial_cash`、`fee_rate`、`minimum_fee` 必填。默认风险比例只是模拟基线，不是已验证最优配置。上游计划的初始仓位上限也会保留，不能因账户上限更宽就扩大首仓。

输出包含每个计划、未执行原因、实际模拟成交价/数量、费用、现金占用、剩余持仓和盯市损益。`net_pnl` 扣除已经发生的模拟费用；持仓未平时不包括未来退出费用。`as_of` 表示已处理的时钟，不代表所有持仓报价均已更新；新开仓对已有持仓的估值过期会拒绝分配。

## 边界与下一轮

fixture 是人工合成数据，股票代码和日期只是协议测试字段，不是真实市场价格，不能用示例损益证明策略盈利。

当前仅接受港股代码和港元账户，使用买一/卖一容量乘参与比例的近似，不模拟真实队列、全深度、冲击、撤单竞争、券商未知订单状态。两次不同时间的盘口可能包含重复挂单量，该近似仍可能高估成交，应在收益研究中进行成交容量敏感性测试。不会将分钟均价自动当成可执行盘口。

费用采用每边费率费用与最低费用取较大值的简化模型，按累计成交额增量计费；实际佣金、税费、碎股、价格档位及账户差异尚待适配。`market_open` 由输入方明确提供，未来盘中接入必须使用可信交易日历，而不是读取不受校验的外部标志。

当前按给定失效价和期限退出，尚未实现 ATR/结构规则自动生成、日损熔断、板块额度、加仓、换仓或策略绩效校准。单笔初始风险是预算而非跳空损失保证。上游 `EntryPlan` 的文字条件不受支持时明确拒绝转换。

新增历史研究入口 `scripts/replay_signal_history.py`，默认只检查数据是否足以支持严格回放；分钟压力模拟必须显式指定假定每手股数、资金、费用、滑点，报告与严格盘口回放分开。详见 `scripts/paper_history/README.md`。生产明细已获授权导出，并完成三个历史分钟假设情景；严格盘口回放和真实组合收益仍未验证，结论见 `discuss/history-paper-study-20260921.md`。

下一轮应补齐点时证券信息、计划快照与新鲜盘口，再比较现行规则与新策略的完整组合净结果。之后才接入盘中影子账户和前端账本，不应把本工具直接放进逐笔回调或开启 FULL 模式。

## 同轮候选修复

`CandidateStateMachine` 为现有强趋势策略的 WATCH 提名单独保留观察状态，不再仅因共享成交额分位不足清空。观察不等于确认，正式确认条件未放宽；数据失效、价格破位、观察到期仍生效，且不会从该观察状态误入其他策略的确认分支。

默认规则版本更新为 `phase15-strong-trend-watch-consistency`，新增状态原因在工作台与提醒格式中使用中文说明。本轮没有部署或重新评估线上策略收益。
